A few self-directed builds showing the kind of ground-up technical work this covers, beyond workflow automation.

Geospatial · records

Parcel ownership lookup from flight paths

Problem: after a drone incident, identifying the affected property and its owner means a manual GIS and county-records lookup.

Approach: upload the incident's KML flight path; the tool resolves the geographic footprint against county tax-parcel boundary data and returns the parcel and ownership record for any point along it.

Status: working tool, self-directed.

Geospatial · visualization

Flight path visualization from KML

Problem: reviewing a flight plan from raw waypoints gives no real spatial sense of the flight.

Approach: upload a KML file; the tool renders it as an interactive, Google Earth-style 3D view of the flight path over real terrain, so the flight can be reviewed visually rather than as a coordinate list.

Status: working tool, self-directed.

Generative CAD · RAG

Spec documents to CAD model + JSON

Problem: turning part specification documents into a usable CAD model and structured data is normally manual drafting and data entry.

Approach: a RAG pipeline that ingests spec documents and generates a corresponding CAD model plus a structured JSON representation of the specs.

Status: proof of concept — the end-to-end pipeline worked and produced usable output, but token cost scaled poorly with document size and some fields were missed on extraction. Confirmed the approach; a production version would need a more targeted extraction strategy.
